# 🐻 Picko

> **Don't know what to do? Let Picko decide.**

Picko is a personalized decision and discovery platform that helps people decide **what to eat, watch, read, play, buy, or do** based on their preferences, mood, context, and previous choices.

Instead of giving users hundreds of options and making them decide again, **Picko makes the decision for them.**

---

## 💡 The Problem

People constantly struggle with simple decisions:

* "Where should we eat?"
* "What should we watch tonight?"
* "What should I read?"
* "What should we do this weekend?"
* "Where should we go with friends?"
* "What should I cook?"
* "What game should I play?"

The problem isn't a lack of choices.

**The problem is having too many choices.**

PickoGo aims to turn:

> **"I don't know."**

into:

> **"Picko knows."**

# 🧠 Personalization

PickoGo should not simply store:

```text
User likes burgers.
User likes thrillers.
User likes cheap restaurants.
```

Instead, the system builds a **personal taste profile**.

Example:

```text
User
│
├── General Preferences
│   ├── Budget Sensitivity
│   ├── Novelty Seeking
│   ├── Social Preference
│   ├── Home Preference
│   └── Adventure Level
│
├── Food
│   ├── Cuisine Preferences
│   ├── Price Preference
│   ├── Delivery Preference
│   └── Dislikes
│
├── Movies
│   ├── Genres
│   ├── Runtime
│   └── Popularity Preference
│
├── Books
│   ├── Genres
│   ├── Length
│   └── Themes
│
└── Activities
    ├── Indoor / Outdoor
    ├── Budget
    └── Social Preference
```

The system should distinguish between:

* **Explicit preferences** — things the user directly tells Picko
* **Behavioral preferences** — patterns learned from usage
* **Feedback** — likes, dislikes, skips, etc.
* **Cross-category signals** — weak signals from other categories

Cross-category signals should influence recommendations without making unsupported assumptions.

For example:

> Choosing cheap food does **not** automatically mean the user has a low income.

Instead, Picko can learn:

```text
food_budget_sensitivity = high
```

# 🔄 Learning Loop

Every interaction can improve the user's profile.

```text
User
 ↓
Answers questions
 ↓
Picko recommends something
 ↓
User chooses / rejects / rates it
 ↓
Preference weights update
 ↓
Future recommendations improve
```

Example:

```text
Picko:
"How was my recommendation?"

❤️ Loved it
😐 It was okay
👎 Not for me
```

Over time, Picko should ask **fewer questions** because it already knows the user.

# ⚙️ Recommendation Engine

The first version does **not require a live AI model**.

The recommendation engine can be built using:

* Rules
* Weighted scoring
* User preferences
* Context
* Historical behavior
* Feedback
* Confidence scores

Example:

```text
score =
    preferenceMatch * 30
  + contextMatch    * 25
  + budgetMatch     * 20
  + distanceMatch   * 10
  + rating          * 10
  + noveltyMatch    * 5
```

The weights can evolve based on user behavior.

# 🤖 AI — Optional

AI should be an enhancement rather than a requirement.

Possible future AI use cases:

* Natural-language requests
* Understanding free-form user input
* Generating explanations
* Extracting preferences from text
* Content generation
* Advanced recommendation models

Example:

> "I'm tired, have 10 JD, and don't want to go far."

AI could convert this into structured context:

```json
{
  "mood": "tired",
  "budget": 10,
  "distance": "short",
  "activity_level": "low"
}
```

The recommendation engine can then make the actual decision.

This keeps the core product functional even without an LLM.
